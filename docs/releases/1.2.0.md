# MeguvizRef 1.2.0

`1.2.0` 已正式发布至 Maven Central，面向 Java 17 与 Android API 27+。本次次版本更新仅新增公开 API，已有签名保持二进制兼容，基于 `1.0.0` 编译的 Java/Kotlin 客户端无需重新编译即可升级。本版本跳过了未发布的 `1.1.0`，版本号与 Meguviz 家族（`meguviz-bom:1.2.0`）保持统一。

## 新增 API

| API | 用途 |
| --- | --- |
| `QuerySpec.method/field/constructor(Class, ...)` | 等价于对应 `builder` 写法的快捷入口 |
| `CodeScope.bindMethod/bindField/bindConstructor(QuerySpec)` | 解析、`requireSingle()` 与绑定一步完成 |
| `CodeScope.open(loader, policy)` | 指定访问策略并使用默认容量 4096 |
| `MethodPlan.call(receiver, args...)`、`ConstructorPlan.create(args...)` | `invoke` / `newInstance` 的可变参数形式，语义不变 |
| `CodeScope.resolveRaw(query)`、`RawResolution` | 返回原始成员而不创建 binding，适合只导出成员的桥接 |
| `CodeScope.isCurrent(loader, identity, epoch)` | 一次加锁核对 loader、identity 和 epoch |
| `ResolutionReceipt.interruptionOrigin()` | 区分单飞等待者于 `Future.get` 中断（`SINGLE_FLIGHT_WAITER`）与其他来源（`UNKNOWN`） |

## 性能改进摘要

1. **计划调用无锁计数与竞争分段**：单线程计划调用耗时从 38.7 ns/op 降至约 17 ns/op，槽位号大于 127 不再装箱；多线程共享同一作用域发生竞争后自动启用按线程分段的 128 字节填充计数单元，2/4/8 线程耗时从 106/228/725 ns/op 降至 19.1/19.4/28.9 ns/op。
2. **缓存与作用域构造优化**：最近使用项无锁快速命中（精确命中 20.3 → 9.3 ns/op，4 线程 477 → 9.7 ns/op）；`identity()` 不再调用 `SecureRandom`，打开加关闭耗时从 293 降至约 70 ns/op（分配从 752 降至 376 B/op）。
3. **结构查询与批量安装复用**：同一作用域复用同一 owner 的成员表并移除多余集合与字符串拼接，155 个方法上的 8 个查询耗时从 53.2 降至约 11 µs/op（分配 189 KB → 27 KB/op）；20 个精确描述符批量解析从 23.8 降至 16.7 µs/op，`resolveRaw` 路径耗时 23.3 µs/op。

> **适用范围与验证说明**：以上微基准数据均采集自宿主 JDK 17 x86-64 环境，不代表 Android ART 运行时或实机设备性能，详见[性能说明](../performance.md)。

## 行为变更与升级提示

- **成员表与类型加载缓存**：结构查询在同一作用域内复用首次枚举成员表，精确描述符查询从第二次查找起按 `(发起加载器, 名称)` 缓存成功加载的类，均在 `advanceCodeEpoch` 或 `close` 时清空。首次枚举后才生效的隐藏 API 豁免需推进 epoch 或新建作用域。
- **关闭协议线性化**：关闭时在锁内先置位基础计数字再置位各分段单元，保证不会有调用在另一个调用被拒后仍然进入；若在途工作在锁内阶段已排空，由 `close()` 同步关闭 Provider。
- **桥接升级建议**：MeguvizHook 的 `hook-ref-bridge` 可使用 `isCurrent` 合并三项检查，并用 `resolveRaw` 避免长会话触及 `binding_capacity` 上限。
- **源码重载兼容性提示**：源码中直接把 `null` 字面量传给 `bindMethod` / `bindField` / `bindConstructor` 的调用方会因新增重载产生歧义，需要显式强转类型；二进制兼容不受影响。

## 验证范围

`1.2.0` 发布构建通过了宿主门禁（186 项核心合同、12 项诊断合同、6 项独立 Java 消费者检查、2 项 Kotlin 消费者检查、5 项旧编译客户端 ABI 检查、Android lint 与 R8 消费构建），核心合同同时在 JDK 25 上运行通过，并辅以可选的 jcstress 与变异检查。实机设备性能回归需在目标 Android 设备上另行测量。
