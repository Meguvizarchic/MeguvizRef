# MeguvizRef 1.1.0（草稿，未发布）

> [!NOTE]
> 本文是下一版本的发布说明草稿。当前 `main` 的版本为 `1.1.0-SNAPSHOT`，尚未发布到任何仓库；发布时需将 `gradle.properties` 改为 `1.1.0` 并按[构建与验证](../development.md)重新验证。

面向 Java 17 和 Android API 27+ 的次版本更新：只新增公开 API，已有签名保持二进制兼容，1.0.0 编译的 Java/Kotlin 客户端无需重新编译。

## 新增 API

| API | 用途 |
|---|---|
| `QuerySpec.method/field/constructor(Class, ...)` | 等价于对应 `builder` 写法的快捷入口 |
| `CodeScope.bindMethod/bindField/bindConstructor(QuerySpec)` | 解析、`requireSingle()` 与绑定一步完成 |
| `CodeScope.open(loader, policy)` | 指定访问策略并使用默认容量 4096 |
| `MethodPlan.call(receiver, args...)`、`ConstructorPlan.create(args...)` | `invoke`/`newInstance` 的可变参数形式，语义不变 |
| `CodeScope.resolveRaw(query)`、`RawResolution` | 返回原始成员而不创建 binding，适合只导出成员的桥接 |
| `CodeScope.isCurrent(loader, identity, epoch)` | 一次加锁核对 loader、identity 和 epoch |

## 性能

以下为主机 JDK 17 x86-64 上的 JMH 结果，**不是 ART 或设备数据**，完整表格与依据见[性能说明](../performance.md)：

- 计划调用不再进入作用域监视器：单线程从 38.7 降到 16.7 ns/op；4 线程共享同一计划从 995 降到 229 ns/op；槽位号大于 127 时不再装箱。
- 缓存命中最近一项无锁返回：精确查询命中从 20.3 降到 9.3 ns/op，4 线程从 477 降到 9.7 ns/op。
- 作用域打开加关闭从 293 降到 67 ns/op，分配从 752 降到 376 B/op（不再使用 SecureRandom）。
- 同一作用域内对同一 owner 的多次结构查询复用成员表：155 个方法的 owner 上 8 个查询从 53.2 降到 10.9 µs/op，分配从 189 KB 降到 27 KB/op。
- 单次结构未命中去掉全成员 visited 集合，描述符每个类型只校验一次。

## 行为说明

- 结构查询在作用域内复用首次枚举的成员表。保留量计入作用域容量，随 epoch 推进与 close 清空，枚举失败不缓存。首次枚举后才生效的隐藏 API 豁免或类结构变化需要推进 epoch 或换作用域。
- `identity()` 仍是进程内唯一的 UUID 格式文本，但不再来自 SecureRandom，不保证不可预测。
- `diagnostics()` 的 `cacheHits` 包含无锁命中，键与含义不变。
- close 的线性化点改为锁内一次原子置位：之前准入的调用参与排空，之后的调用直接被拒绝，被拒绝的调用方不会执行 Provider 关闭。拒绝消息不变。

## 升级提示

- MeguvizHook 的 Ref 桥接可用 `isCurrent` 替换 `usesLoader`/`codeEpoch`/`identity` 三次检查，用 `resolveRaw` 避免长会话因导出累计触发 `binding_capacity`；这需要把依赖固定为包含这些 API 的版本。
- 源码中把 `null` 字面量直接传给 `bindMethod`/`bindField`/`bindConstructor` 的调用会因新增重载产生歧义，需要显式转换类型；二进制不受影响。
