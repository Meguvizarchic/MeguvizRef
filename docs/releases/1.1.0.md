# MeguvizRef 1.1.0（草稿，未发布）

> [!NOTE]
> 本文是下一版本的发布说明草稿。当前 `main` 的版本为 `1.1.0-SNAPSHOT`，尚未发布到任何仓库；发布步骤见文末的[发布前检查](#发布前检查)。

面向 Java 17 和 Android API 27+ 的次版本更新：只新增公开 API，已有签名保持二进制兼容，1.0.0 编译的 Java/Kotlin 客户端无需重新编译。本周期分两轮完成，第 2 轮没有新增公开 API。

## 新增 API

| API | 用途 |
|---|---|
| `QuerySpec.method/field/constructor(Class, ...)` | 等价于对应 `builder` 写法的快捷入口 |
| `CodeScope.bindMethod/bindField/bindConstructor(QuerySpec)` | 解析、`requireSingle()` 与绑定一步完成 |
| `CodeScope.open(loader, policy)` | 指定访问策略并使用默认容量 4096 |
| `MethodPlan.call(receiver, args...)`、`ConstructorPlan.create(args...)` | `invoke`/`newInstance` 的可变参数形式，语义不变 |
| `CodeScope.resolveRaw(query)`、`RawResolution` | 返回原始成员而不创建 binding，适合只导出成员的桥接 |
| `CodeScope.isCurrent(loader, identity, epoch)` | 一次加锁核对 loader、identity 和 epoch |

## 性能

以下为主机 JDK 17 x86-64 上的 JMH 结果，**不是 ART 或设备数据**，完整表格、依据与验证方法见[性能说明](../performance.md)。

- 计划调用不再进入作用域监视器：单线程从 38.7 降到约 17 ns/op；槽位号大于 127 时不再装箱。
- 多线程共享同一作用域的计划调用：观察到竞争后改用按线程分段的准入计数，2/4/8 线程从 106/228/725 降到 19.1/19.4/28.9 ns/op（同期交替测量的中位数）；无竞争的单线程调用和作用域开关的成本与分配不变。
- 缓存命中最近一项无锁返回：精确查询命中从 20.3 降到 9.3 ns/op，4 线程从 477 降到 9.7 ns/op。
- 作用域打开加关闭从 293 降到约 70 ns/op，分配从 752 降到 376 B/op（不再使用 SecureRandom）。
- 同一作用域内对同一 owner 的多次结构查询复用成员表：155 个方法的 owner 上 8 个查询从 53.2 降到约 11 µs/op，分配从 189 KB 降到 27 KB/op。
- 安装批量（`java.lang.String` 上 20 个描述符目标，一个作用域）：完整精确描述符从 23.8 降到 16.7 µs/op，桥接式结构查询加 `resolveRaw` 从 25.7 降到 23.3 µs/op，分配分别降低约 16% 和 17%。
- 单次结构未命中去掉全成员 visited 集合，描述符每个类型只校验一次，查询构造不再为 owner 校验拼接字符串，single-flight 无等待者时不创建 future。

## 行为说明

- 结构查询在作用域内复用首次枚举的成员表。保留量计入作用域容量，随 epoch 推进与 close 清空，枚举失败不缓存。首次枚举后才生效的隐藏 API 豁免或类结构变化需要推进 epoch 或换作用域。
- 精确描述符查询从同一作用域的第二次查找起，按（发起加载器身份，名字）缓存 owner 与类型的成功加载结果：命中与重复调用 `Class.forName` 得到同一个类，失败不缓存，条目数不超过容量，随 epoch 与 close 丢弃。作用域打开期间强持有这些类；安全管理器对同一（加载器，名字）的检查只在首次查找时执行。
- `identity()` 仍是进程内唯一的 UUID 格式文本，但不再来自 SecureRandom，不保证不可预测。
- `diagnostics()` 的键与含义不变：`cacheHits` 包含无锁命中；`inFlight` 是在途计数之和，静止时精确，并发变化时与 `LongAdder.sum()` 一样不一定对应某一时刻。
- close 的线性化：锁内原子置位关闭标志；出现过竞争的作用域先置位基础计数再置位各分段计数，因此不会有调用在另一调用被拒绝之后被接受。之前准入的调用参与排空，之后的调用直接被拒绝，被拒绝的调用方不会执行 Provider 关闭。拒绝消息不变。
- 出现过竞争的作用域上，若在途工作在 close 的锁内阶段就已结束，Provider 由 close 同步关闭，关闭失败照常从 close 抛出；否则仍由最后结束的在途工作关闭。

## 升级提示

- MeguvizHook 的 Ref 桥接可用 `isCurrent` 替换 `usesLoader`/`codeEpoch`/`identity` 三次检查，用 `resolveRaw` 避免长会话因导出累计触发 `binding_capacity`，并可在一个作用域内批量解析同一 owner 上的多个描述符目标；这需要把依赖固定为包含这些 API 的版本。
- 源码中把 `null` 字面量直接传给 `bindMethod`/`bindField`/`bindConstructor` 的调用会因新增重载产生歧义，需要显式转换类型；二进制不受影响。
